# רופא רכב (Car Doctor)

אפליקציה לבדיקת תקלות ברכב דרך מתאם OBD-II מסוג ELM327, בשביל המשתמש הביתי וחובב הרכב.

**הורדת האפליקציה (Android):** [הגרסה העדכנית, APK חתום](https://github.com/d0548450344-dotcom/rofeh-rechev/releases/latest/download/rofeh-rechev.apk). כל גרסה חדשה מותקנת מעל הקודמת ושומרת את הנתונים.

## מה האפליקציה עושה
- **סריקה מהירה:** קודי תקלה שמורים וממתינים, מוכנות מערכות לטסט, ונתונים חיים (סל"ד, מהירות, טמפרטורת קירור, מצערת, מתח).
- **הסבר בעברית** ל-347 קודי תקלה כלליים. המאגר מתעדכן אונליין. קוד שאינו במאגר מוסבר לפי המבנה שלו, עם ציון שהמשמעות לא אומתה.
- **מחיקת קודים עם הגנות:**
  - שני אישורים.
  - רק אחרי סריקה שמורה.
  - רק כשהמנוע כבוי והרכב עומד.
  - אחר כך רצה סריקת אימות אוטומטית.
- **אין צריבה, אין שיפור כוח ואין שינוי תוכנה ביחידות.** פקודות כאלה חסומות בקוד, ובדיקות אוטומטיות מוודאות זאת.
- **רכב מדומה** לתרגול, בלי מתאם.

## מתאמים נתמכים
| מתאם | אפליקציית Android | גרסת רשת (Chrome / Edge) |
|---|---|---|
| ELM327 Bluetooth רגיל | ✓ (מצמדים קודם בהגדרות הטלפון) | ✓ במחשב, דרך יציאת COM |
| ELM327 Bluetooth LE | ✓ | ✓ (לא באייפון) |
| ELM327 Wi-Fi | ✓ | ✗ (דפדפן לא יכול לפתוח חיבור כזה) |
| ELM327 USB | — | ✓ במחשב |

רק מנוע ופליטות נקראים, לפי תקן OBD-II. ABS, כריות אוויר ומרכב דורשים פרוטוקולי יצרן, ולא נסרקים.

## מבנה המאגר
```
android/            אפליקציית Android (Kotlin, Jetpack Compose)
  transport/        ערוצי תקשורת: זרם נתונים כללי, Wi-Fi (TCP)
  protocol/         OBD-II ו-ELM327: פענוח, וחסימת פקודות כתיבה וצריבה
  core/             מודל, כללי אבחון, ספסל הסריקה, מאגר הקודים
  simulation/       רכב ומתאם מדומים
  live/             מתאם אמיתי לרכב (ELM327)
  data/             שמירת המוסך בקובץ JSON
  app/              מסכים; app/link: Bluetooth, BLE, Wi-Fi, עדכון קודים
  checks/           בדיקות ארכיטקטורה (גבולות בין מודולים, אין צריבה)
src/                גרסת הרשת (React, TanStack Start)
  domain/ engine/   מודל וכללי אבחון
  live/             מנהל ELM327, Web Bluetooth ו-Web Serial
  store/            מצב האפליקציה
shared/dtc/         מאגר קודי התקלה, המקור היחיד לשתי הגרסאות
scripts/gen-dtc.mjs מייצר את טבלאות הקודים לשתי הגרסאות מהקובץ המשותף
```

**קבצים של סביבת Grok:** `AGENTS.md`, `startup.sh`, `server/`, `public/__grok/`, `scripts/grok-*`, `src/lib/auth`, `src/lib/app-data` ודומיהם מאפשרים ל-Grok להציג תצוגה מקדימה של גרסת הרשת. האפליקציה עצמה לא משתמשת בהם. הבדיקות שלהם רצות בנפרד (`npm run test:platform`), וחלקן נכשלות מחוץ לסביבת Grok.

## פיתוח
**גרסת הרשת** (Node 22):
```bash
npm ci
npm run dev        # http://localhost:8080
npm test           # בדיקות האפליקציה
npm run typecheck
npm run build
```

**אפליקציית Android** (JDK 17, Android SDK):
```bash
cd android
./gradlew test               # כל הבדיקות
./gradlew :app:assembleDebug
```

**עדכון מאגר הקודים:** עורכים את `shared/dtc/generic-dtc-he.json`, ואז מריצים `npm run gen:dtc`. אחרי מיזוג ל-main, האפליקציות המותקנות מקבלות את העדכון לבד.

## בנייה ושחרור
- **GitHub Actions** בונה ובודק כל שינוי: `Android` ו-`Web`.
- כל מיזוג ל-main יוצר APK חתום, ומפרסם אותו בקישור הקבוע שלמעלה.
- מפתח החתימה שמור ב-Secrets של המאגר (`SIGNING_KEYSTORE_B64`, `SIGNING_PASSWORD`), ואינו נמצא במאגר עצמו. גיבוי של המפתח נמצא אצל בעל הפרויקט.
